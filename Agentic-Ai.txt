# 1. PROJECT OVERVIEW

**What problem does this solve?**
Aegis Protocol solves the critical problem of real-time digital misinformation, coordinated financial manipulation, and brand reputation attacks. In an era where fake news, AI-generated deepfakes, and automated bot swarms can wipe out millions in market cap or destroy a person's reputation in minutes, traditional fact-checking is too slow.

**Why is this problem important in real-world context?**
Financial markets and brand equity rely on public perception. A single unverified tweet about a CEO stepping down or a fake FDA advisory can trigger algorithmic trading sell-offs. Early detection of these anomalies prevents unwarranted financial panic and protects consumer trust.

**Who are the users?**
- **Financial Analysts & Traders (Scout Agent):** Looking to protect portfolios from fake-news-induced volatility.
- **PR Agencies & Public Figures (Personal Watch & Trending Agents):** Needing early warnings of viral defamation or harassment.
- **Corporate Brand Managers (BrandShield Agent):** Monitoring for counterfeit listings and manipulated review bombing.

**What makes this project unique?**
It moves beyond static keyword monitoring into **Agentic AI swarms**. Instead of just flagging a keyword, Aegis relies on targeted Gemini 2.0+ models to simultaneously cross-reference financial data (Yahoo Finance Z-scores) with real-time news aggregation across multiple platforms (Twitter, Bloomberg, Reddit), autonomously assigning a verdict and severity score in under 30 seconds.

# 2. SYSTEM ARCHITECTURE

**System Flow:**
Input (Market Data / Social Feeds / User Queries) → Processing (Netlify Serverless Proxy + Render Backend) → AI Swarm Verification (Gemini 2.5 Flash) → Output (Live DOM Updates / Verdict Rendering).

**Core Components:**
- **Frontend (Presentation Layer):** A high-performance Vanilla JS Single Page Application (SPA) utilizing CSS custom properties for a hardware-accelerated "agentic cyberpunk" aesthetic. No bloated frameworks; optimal for instant load times.
- **API Gateway & Proxy (Netlify Functions):** A serverless Node.js proxy (`/.netlify/functions/gemini`) handles CORS preflighting and API key obfuscation. It implements multi-model fallback routing and rate-limit backoffs.
- **Backend (Render):** A FastAPI/Node.js backend handling heavy background processing, database hydration, and cron-based polling (`/api/dashboard/claims`).
- **ML Models (Gemini Over API):** Google's `gemini-2.5-flash` and `gemini-2.0-flash` endpoints, accessed via `v1beta`.
- **External Services:** Yahoo Finance API (for live ticker data), CORSProxy/AllOrigins (for circumventing legacy API CORS restrictions).

**Architecture Step-by-Step:**
1. **User Input:** User enters a ticker (e.g., `TATAMOTORS.NS`) into the frontend UI.
2. **Data Aggregation:** Frontend makes parallel async requests to Yahoo Finance (via proxy fallbacks) to fetch 5-day historical closing prices and volume.
3. **Statistical Analysis:** Frontend calculates price drop percentages, moving averages, and rolling Z-scores to flag statistical anomalies.
4. **Prompt Orchestration:** A dynamic prompt is constructed injecting the live financial state and instructing the AI to simulate multi-platform news scraping.
5. **AI Inference:** The payload is sent via the Netlify serverless function (which securely attaches `GEMINI_KEY_n`) to the Gemini API. 
6. **Delivery:** The AI returns a strict JSON array of threats, which the frontend parses and renders into severity-coded threat cards.

# 3. DATA FLOW PIPELINE

**Where does data come from?**
1. **Quantitative Data:** Yahoo Finance API (pricing, volume, metadata).
2. **Qualitative Data:** Simulated/Live scrapes from X/Twitter, Reddit, Bloomberg, Economic Times, Trustpilot.

**Processing & Transformations:**
- **Preprocessing:** Stock data arrays are flattened; historical bounds are calculated to establish a baseline mean.
- **Feature Engineering:** Calculation of the **Z-Score** (Standard Deviation from the Mean) to determine if a drop is an organic market move or an algorithmic anomaly.
- **Inference Flow:** 
  `Raw Ticker + Z-Score + Drop %` → `Injected into Context-Aware Prompt` → `Gemini 2.5 LLM` → `Structured JSON Output containing Sentiment (-100 to 100), Target, and Threat Boolean`.
- **Storage:** Static claims and cached verdicts are temporarily stored in local memory (`allClaims` array) or the Supabase database.

# 4. MACHINE LEARNING / AI LOGIC

**What model is used?**
Google's **Gemini 2.5 Flash** (Primary) with a fallback to **Gemini 2.0 Flash**.

**Why this model?**
Latency is the enemy of trading and PR crisis management. Gemini Flash variants offer near-instant tokens-per-second generation rates, critical for a platform boasting sub-30-second response times. Furthermore, Gemini's native JSON structuring enforces reliable application state.

**Inputs / Outputs:**
- **Input:** Highly constrained system prompts requiring strict roleplay ("You are a financial intelligence AI...") combined with real-time variables.
- **Output:** A strict, validated JSON array mapping to frontend TypeScript/JS interfaces: `{ title, source, summary, type, is_threat, severity, sentiment }`.

**Limitations & Improvements:**
- *Limitation:* The AI currently simulates real-time Twitter/News scraping via hallucinated intelligence based on its training cutoff or lightweight search.
- *Improvement:* Implement a dedicated RAG (Retrieval-Augmented Generation) pipeline using Firecrawl or Apify to ingest literal URL text before feeding it to Gemini.

# 6. PERFORMANCE & SCALABILITY

**Expected Load & Bottlenecks:**
- **Bottleneck 1: Gemini Rate Limits.** We are using the free tier which imposes a 15 RPM (Requests Per Minute) limit. 
- **Bottleneck 2: Cold Starts.** Render's free tier spins down the backend after 15 minutes of inactivity, causing 50–90 second delays on the first request.

**How to Scale:**
1. **API Key Rotation:** We currently implemented a round-robin rotation of 3 API keys in `gemini.js` to triple the RPM limit.
2. **Model Cascading:** The system fails over sequentially: `2.5-flash` → `2.0-flash`, maximizing total quota.
3. **Caching (Redis):** If 10 users search for `TATAMOTORS.NS` in a 5-minute window, the API request shouldn't hit Gemini 10 times. A Redis layer should cache the JSON response with a 5-minute TTL.
4. **Async Jobs:** Move backend scraping to Celery/RabbitMQ workers so the frontend doesn't hang waiting for a monolithic HTTP response.

# 7. FAILURE MODES

**Where can the system fail?**
1. **Model Hallucination:** Gemini flags a legitimate press release as a "defamatory attack." 
2. **API Failure (429/500/503):** Google's API goes down, or we hit rate limits too fast.
3. **Data Drift / Target Drift:** Yahoo Finance changes its undocumented `/v8/finance/chart` endpoint structure, breaking the frontend JSON parser.

**How to detect & fix:**
- **Try/Catch Blocks containing Fallbacks:** Implemented deeply in `scout-agent.html` and `gemini.js`. If Yahoo fails, the UI gracefully renders an "N/A" state but still proceeds to AI analysis.
- **JSON Validation Errors:** The frontend uses regex cleanup (`.replace(/^```json/...)`) to strip markdown fences if the LLM ignores the strict output command.

# 8. MONITORING & OBSERVABILITY

**What is monitored:**
- **Serverless Logs:** Netlify function logs output critical states: arrays of exhausted keys, 429 rate limit triggers, and `v1beta` HTTP errors.
- **Backend Health:** A `/api/claims` ping acts as a live heartbeat on the Render environment, automatically clearing the "Backend waking up" UI banner.

**Enterprise Improvements Needed:**
- Implement **Datadog or Sentry** in the frontend to catch `TypeError: Failed to fetch` errors generated by ad-blockers blocking CORS proxies.
- Add an **MLflow** or **LangSmith** layer to log prompt token usage and track how often the JSON schema breaks in production.

---

# 9. SECURITY & RELIABILITY

- **API Security:** The frontend never exposes `AIzaSy...` keys. They reside purely on the server (Netlify/Render env vars).
- **CORS Protection:** The Netlify proxy explicitly defines an `OPTIONS` preflight handler to secure browser invocations.
- **Input Validation:** User inputs (`tickerInput.value.trim()`) are stripped of whitespace and encoded (`encodeURIComponent`) before being appended to proxy URLs to prevent injection attacks and malformed network requests.
